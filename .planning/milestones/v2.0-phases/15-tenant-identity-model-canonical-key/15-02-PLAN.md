<objective>
Build the CI verification harness for the entitlement-plane backfill: a test-only fixture that
simulates the Strapi-created `tenant_entitlements` table in ephemeral Postgres, an idempotent backfill
SQL that rewrites `'default'` rows to the canonical UUID, an assertion SQL that proves zero `'default'`
rows survive, and a CI workflow that wires them together so a regression fails the build.

CRITICAL ARCHITECTURE FACT (from research "Don't Hand-Roll"): the backfill is NOT a `db/migrations/`
file. That directory is run by the `db-migrate` init container against the **n8n** DB.
`tenant_entitlements` lives in the **strapi** DB (Strapi auto-creates it). A migration file there would
hit the wrong database. The backfill is therefore a standalone CI-assertion SQL + the seeder fix
(Plan 15-03) — not a migration.

Purpose: Make Phase 15 success criterion #2 CI-verifiable — "seed/backfill SQL runs green against an
ephemeral CI Postgres" — and provide the Wave-0 assertion infrastructure the validation strategy
demands.
Output: one fixture, two assertion SQL files, one CI workflow.
</objective>
