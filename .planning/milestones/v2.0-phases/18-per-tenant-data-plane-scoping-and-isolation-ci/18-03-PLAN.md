(1) A→B read blocked: `SELECT COUNT(*) FROM orders WHERE tenant_id='…0001' AND order_id='bbbbbbbb…'`
    must be 0; else `RAISE EXCEPTION 'FAIL: tenant A read tenant B order'`.
(2) B→A read blocked: symmetric (`tenant_id='…00b2' AND order_id='aaaaaaaa…'` -> 0).
(3) A→B write blocked: `WITH upd AS (UPDATE orders SET status='cancelled' WHERE order_id='bbbbbbbb…'
    AND tenant_id='…0001' RETURNING 1) SELECT COUNT(*) INTO v_rows FROM upd;` must be 0 rows affected;
    else FAIL.
(4) Non-defaultable write: a nested `BEGIN ... EXCEPTION WHEN not_null_violation THEN v_failed:=true; END;`
    wrapping `INSERT INTO orders(order_id, restaurant_id, channel, "customer_userId", total_amount, status)
    VALUES ('cccccccc…','…0000','whatsapp','userC',50,'confirmed');` (note: tenant_id OMITTED). After
    the block, `IF NOT v_failed THEN RAISE EXCEPTION 'FAIL: INSERT without tenant_id succeeded'`. Do
    NOT use SAVEPOINT/ROLLBACK TO SAVEPOINT (Pitfall 5).
(5) FK enforcement: nested `BEGIN ... EXCEPTION WHEN foreign_key_violation THEN v_failed:=true; END;`
    wrapping an INSERT with `tenant_id='99999999-9999-9999-9999-999999999999'` (not in tenants); FAIL
    if it succeeds.

Use the exact UUIDs from &lt;interfaces&gt;. Each block declares its own vars. Keep it a single file
