<objective>
Rewrite `db/migrations/2026-04-06_saas_modules_entitlements.sql` into a **live-safe**, idempotent
migration and relocate it to `db/migrations-strapi/` (the strapi-DB migration directory introduced in
Plan 16-03). The current file (read in full below) uses a bare
`ALTER TABLE tenant_entitlements ADD CONSTRAINT uq_tenant_module UNIQUE (...)` that (a) takes an
`ACCESS EXCLUSIVE` lock and (b) **fails outright if any duplicate `(tenant_id, module_key)` row
exists**. The rewrite replaces that with the Postgres-standard zero-downtime pattern:
read-only duplicate probe -> dedupe (keep latest `activated_at`) -> `CREATE UNIQUE INDEX
CONCURRENTLY IF NOT EXISTS` -> `ALTER TABLE ... ADD CONSTRAINT ... USING INDEX`, with
`lock_timeout`/`statement_timeout` set and full re-run idempotency.

This plan also creates the **Wave 0** CI fixture and assertion files this migration is verified against
(the migration is the production code; the fixture + assertion are its tests). Plan 16-03 wires both
the migration and these assertions into `docker-compose.base.yml` and `phase-16-assertions.yml`.

Purpose: Make the DB-01 constraints safe to apply on a live, possibly-duplicated production table
without locking out concurrent reads/writes and without erroring on pre-existing duplicates.
Output: One rewritten strapi-DB migration file + one CI fixture + one CI assertion file.

🔴 VPS-DEFERRED: applying this migration against the production strapi DB is deferred to a
prod-connected session (called out in the migration header comment). This plan is fully
local/CI-verifiable.
</objective>

    The file must be a sequence of TOP-LEVEL statements (NOT all wrapped in one transaction — the
    CONCURRENTLY step is run by 16-03's apply wrapper outside any txn, direct to postgres:5432). Structure
    the file so each logical step is its own statement/block:

    HEADER comment block:
    - "Live-safe SaaS modules & entitlements migration. Strapi DB target."
    - "🔴 VPS apply deferred to a prod-connected session."
    - "DELIVERY: applied by the strapi-DB pass in db-migrate (PGDATABASE=strapi). The CONCURRENTLY
       step is executed direct-to-postgres:5432 (bypassing pgBouncer POOL_MODE=transaction) by the
       16-03 apply wrapper — CREATE INDEX CONCURRENTLY cannot run inside a transaction block."

    STEP 0 — timeouts (top-level, applies to the session):
      SET lock_timeout = '5s';
      SET statement_timeout = '120s';

    STEP 1 — read-only duplicate PROBE (DO $$ ... RAISE NOTICE only, no failure):
      Count duplicate (tenant_id, module_key) groups in tenant_entitlements and duplicate key groups
      in product_modules; RAISE NOTICE 'PROBE: % entitlement dup-groups, % product_module dup-groups'.
      MUST NOT raise an exception (a probe never fails the migration).

    STEP 2 — DEDUPE tenant_entitlements (keep latest activated_at):
      DELETE FROM tenant_entitlements WHERE id NOT IN (
        SELECT DISTINCT ON (tenant_id, module_key) id FROM tenant_entitlements
        ORDER BY tenant_id, module_key, activated_at DESC NULLS LAST, id DESC);

    STEP 3 — DEDUPE product_modules (keep latest id as the survivor):
      DELETE FROM product_modules WHERE id NOT IN (
        SELECT DISTINCT ON (key) id FROM product_modules ORDER BY key, id DESC);

    STEP 4 — CONCURRENTLY index builds (BARE top-level statements, NO DO block, NO transaction):
      CREATE UNIQUE INDEX CONCURRENTLY IF NOT EXISTS uq_tenant_module_idx
        ON tenant_entitlements (tenant_id, module_key);
      CREATE UNIQUE INDEX CONCURRENTLY IF NOT EXISTS uq_product_module_key_idx
        ON product_modules (key);
      Add an inline comment above these two: "-- CONCURRENTLY: run OUTSIDE any txn, direct to
      postgres:5432 (see 16-03 wrapper). IF NOT EXISTS makes re-run idempotent."

    STEP 5 — ATTACH index as constraint (DO $$ guarded on constraint existence; SET timeouts already done):
      DO $$ BEGIN
        IF NOT EXISTS (SELECT 1 FROM pg_constraint WHERE conname='uq_tenant_module') THEN
          ALTER TABLE tenant_entitlements ADD CONSTRAINT uq_tenant_module UNIQUE USING INDEX uq_tenant_module_idx;
        END IF;
      END $$;
      (repeat an analogous DO block for uq_product_module_key USING INDEX uq_product_module_key_idx.)

    STEP 6 — the SAFE-as-is objects (copy verbatim from the source file, they are already idempotent):
      idx_entitlements_tenant, idx_entitlements_module, idx_entitlements_active (CREATE INDEX IF NOT EXISTS),
      entitlement_audit_log table (CREATE TABLE IF NOT EXISTS — KEEP tenant_id VARCHAR(255) per ADR 0001;
      the VARCHAR->uuid migration is explicitly deferred to Phase 19), idx_entitlement_audit_tenant.

    Do NOT use bare `ALTER TABLE ... ADD CONSTRAINT UNIQUE (cols)` anywhere (the anti-pattern). Do NOT
    wrap CONCURRENTLY in a DO block or BEGIN/COMMIT.

    IMPORTANT — local verification note for the executor: in a single-`psql -f` run STEP 4's

    each statement auto-commits unless inside BEGIN. To verify locally, apply the file with

    direct postgres, NOT pgbouncer — see 16-03). The fixture (Task 0) must be applied first.
