<objective>
Insert a `channel_identities` resolution rung into the three inbound adapters (W1_IN_WA, W2_IN_IG,
W3_IN_MSG) and rewrite each `B0 - Apply Auth Context` Code node so the Meta-channel auth modes
(`meta_signature`, `legacy_shared`) take the **real** `(tenant_id, restaurant_id)` from the lookup
instead of `DEFAULT_TENANT_ID` / hardcoded UUIDs. An unknown identity fails closed via the existing
deny branch.

Purpose: This is the core TEN-03 surgery — it closes the inbound tenant-derivation gap so a second
restaurant can be onboarded by adding a `channel_identities` row, with no workflow code change, and so
an unknown phone number / page id can never silently route to tenant `'default'`.

Output: Three modified workflow JSON files, each with a new Postgres resolver node, a Code shim that
namespaces the result, and a rewritten fail-closed `B0 - Apply Auth Context`. The W2/W3 duplicate
`const metaSigValid` latent bug is eliminated in the same rewrite.

🔴 VPS DEFERRED: importing/activating the updated workflows on production n8n is deferred to a
prod-connected session (per ROADMAP Phase 17 success-criterion VPS sub-step).
</objective>
