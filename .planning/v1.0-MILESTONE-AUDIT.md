## Executive Summary

8 of 10 phases have passing VERIFICATION.md files. **27/34 requirements satisfied** at code/CI level, but **7 requirements are unsatisfied at VPS runtime** due to two root causes:

1. **W_QUEUE_METRICS credential gap** — PG and Redis credential IDs use `$env.*` expressions that evaluate to empty strings (env vars not set in docker-compose). This silently breaks METR-01, METR-02, METR-04, and METR-05 on VPS.

2. **Phase 3 DB migration not applied to VPS** — `ops.workflow_audit` table does not exist on VPS, breaking AUDIT-02 (inbound adapter audit writes), AUDIT-03 (admin dashboard audit view), and AUDIT-04 (W_AUDIT_ARCHIVE activation).

Additionally, AUDIT-03 has a code-level bug: `AuditLogView.tsx` uses `VITE_API_URL` (not declared in `docker-compose` build args) causing the fetch URL to resolve to `/api/webhook/...` — a completely unrouted path.

## Unsatisfied Requirements

### METR-01 — n8n queue depth exported as metric

**Root cause:** W_QUEUE_METRICS.json PG credential `id: "={{$env.N8N_DB_CREDENTIAL_ID || ''}}"`. `N8N_DB_CREDENTIAL_ID` absent from `docker-compose.hostinger.prod.yml` env block and empty in `.env` → empty credential ID → node fails at runtime.
**Code artifacts:** ✅ W_QUEUE_METRICS.json exists with correct logic
**Fix:** Add `N8N_DB_CREDENTIAL_ID: 1mZZJEscADgQ8InR` to n8n-main/worker env in compose, OR hardcode `"id": "1mZZJEscADgQ8InR"` in W_QUEUE_METRICS.json

### METR-02 — Workflow error rate tracked

**Same root cause as METR-01.** `failed_24h` count is part of the same PG query.

### METR-04 — Queue depth alert at > 50 for 5+ minutes

**Cascade from METR-01.** Alert evaluates queue depth which cannot be read.

### METR-05 — Disk usage alert at > 80%

**Root cause:** W_QUEUE_METRICS.json disk check uses `stat -f -c '%a %s %b' /` (GNU coreutils syntax). Alpine/busybox `stat` rejects this → exception caught → `diskUsedPct = -1` → alert guard `>= 0` never satisfied → DISK_ALERT never emits.
**Note:** Phase 07 VERIFICATION.md claimed this was fixed with `df -k /`. Current file uses `stat -f -c`. Likely regression from Phase 09 credential patching that overwrote W_QUEUE_METRICS.json.
**Fix:** Replace `stat -f -c` with `df -k /` disk check (restore Phase 07 fix) + apply credential ID fix.

### AUDIT-02 — Inbound adapters write audit entries on start/end

**Root cause:** `ops.workflow_audit` table NOT applied to VPS. Phase 3 migration file exists locally (`db/migrations/2026-03-23_p3_workflow_audit.sql`) but was never run on VPS per 09-01-SUMMARY.md blocker 1.
**Code artifacts:** ✅ W_AUDIT_WRITE.json activated on VPS; audit hooks in W1/W2/W3 with continueOnFail
**Fix:** Run migration on VPS → `docker exec current-postgres-1 psql -U strapi -d strapi < db/migrations/2026-03-23_p3_workflow_audit.sql`

### AUDIT-03 — Audit log queryable from admin dashboard

**Root cause:** 4 compounding defects:

1. **`VITE_API_URL` not in compose build args** — Dockerfile declares `ARG VITE_API_URL` but `docker-compose.hostinger.prod.yml` admin-dashboard build args contain only `VITE_DOMAIN`, `VITE_STRAPI_URL`, `VITE_N8N_URL`. Build time value is empty string → `apiBase` falls back to `'/api'` → `AuditLogView.tsx:112` constructs `/api/webhook/v1/internal/audit-log` — an unrouted local path that never reaches n8n.

2. **ops.workflow_audit table missing on VPS** → W_AUDIT_QUERY SQL fails even when reachable.

3. **countQuery never executes** — W_AUDIT_QUERY builds `countQuery` in parse step but has no second PG node to execute it. `total: items.length` returns current-page count → pagination shows 1 page always.

4. **UI filters ignored** — AuditLogView sends `?status=failed&channel=whatsapp` but W_AUDIT_QUERY SQL ignores both — no WHERE clauses built for status/channel.

**Fix:** Add `VITE_API_URL: https://api.${DOMAIN_NAME}` to admin-dashboard compose build args. Rebuild image. Also apply ops migration.

### AUDIT-04 — Audit entries archived after 90 days

**Root cause:** W_AUDIT_ARCHIVE NOT activated on VPS. n8n 2.x scheduleTrigger incompatibility (`propertyValues[itemName] is not iterable`). Commit 8bd4c33 applied local fix but workflow was not re-imported/activated on VPS.
**Fix:** Re-import W_AUDIT_ARCHIVE.json on VPS and `UPDATE workflow_entity SET active = true WHERE name = 'W_AUDIT_ARCHIVE'`.
