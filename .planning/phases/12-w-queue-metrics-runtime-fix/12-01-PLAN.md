# Phase 12: W_QUEUE_METRICS Runtime Fix — Plan 01

**Created:** 2026-06-20
**Phase goal:** Make METR-01, METR-02, METR-04, METR-05 fire on VPS by fixing the two runtime defects in `workflows/W_QUEUE_METRICS.json` identified by the 2026-04-04 milestone audit (INT-02, WARN-04).

<objective>
Replace the empty `$env.*` credential-ID expressions (PG + Redis) with the real hardcoded n8n credential IDs, and replace the GNU-only `stat -f -c` disk check with the POSIX `df -k /` form that works on the Alpine/busybox n8n runtime.
</objective>

## Root cause (from audit)

- **INT-02 / METR-01,02,04:** PG node credential `id: "={{$env.N8N_DB_CREDENTIAL_ID || ''}}"` and the Redis nodes' `id: "={{$env.REDIS_CREDENTIAL_ID || ''}}"` evaluate to `''` because the env vars are absent from compose — the nodes fail at runtime, so no queue-depth/error-rate metrics or queue alert.
- **WARN-04 / METR-05:** the `B0 - Compute Metrics` node computes disk usage via `require('child_process').execSync("stat -f -c '%a %s %b' /")`. busybox `stat` rejects `-f -c`, the exception is caught, `diskUsedPct` stays `-1`, and the `>= diskAlertPct` guard never fires.

## Tasks

1. Hardcode PG credential id → `1mZZJEscADgQ8InR` (the value working audit workflows like `W_AUDIT_ARCHIVE.json` already use for the n8n DB).
2. Hardcode Redis credential id → `43SDqJYMGa6RvFqW` (the value documented in Phase 09's credential-injection plan, `09-01-PLAN.md`). Applies to both Redis nodes (get + set queue counter).
3. Replace the `stat -f -c` disk block with `df -k /` parsing (POSIX; last output line, columns 1K-blocks/Used).
4. Verify: JSON still valid; no `CREDENTIAL_ID` env expressions remain; the `df -k /` logic returns a percentage in `[0,100]` under Node.
