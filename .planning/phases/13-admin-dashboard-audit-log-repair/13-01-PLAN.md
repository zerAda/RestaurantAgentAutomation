# Phase 13: Admin Dashboard Audit-Log Repair — Plan 01

**Created:** 2026-06-20
**Phase goal:** Make AUDIT-03 (audit log queryable from the admin dashboard) work end-to-end by fixing the build-arg wiring and the three W_AUDIT_QUERY defects the 2026-04-04 audit identified (INT-03, WARN-01/02/03).

<objective>
The admin dashboard's AuditLogView must reach the n8n audit-query webhook at the correct URL, and W_AUDIT_QUERY must return a correct global total and honour the limit/status/channel parameters the UI sends.
</objective>

## Root cause (from audit)

- **INT-03:** `admin-dashboard/Dockerfile` declares `ARG VITE_API_URL`, but no compose file passes it, so the baked value is empty and `apiBase` falls back to `/api` → fetch URL `/api/webhook/v1/internal/audit-log` is unrouted. `AuditLogView.tsx` also declares an unused `n8nBase`.
- **WARN-01:** `countQuery` is built in the parse node but no PG node runs it; `B0 - Format Response` returns `total: items.length` (page count, ≤ limit).
- **WARN-02:** the UI sends `limit`; the parse node reads `qs.page_size` → UI page size ignored, backend defaults to 50.
- **WARN-03:** the UI sends `status`/`channel`; the parse node builds no WHERE clauses for them → filters silently ignored.

## Tasks

1. **Compose build arg:** add `VITE_API_URL: https://api.${DOMAIN_NAME}` to the `admin-dashboard` build args in `docker-compose.hostinger.prod.yml` and `docker-compose.base.yml`.
2. **AuditLogView.tsx:** remove the dead, unused `n8nBase` constant (apiBase is the one used). Also clears the `no-unused-vars` lint error for this file.
3. **W_AUDIT_QUERY.json — limit alias:** parse node reads `qs.page_size || qs.limit || '50'`.
4. **W_AUDIT_QUERY.json — filters:** parse node adds `AND status = '…'` and `AND channel = '…'` WHERE clauses (single-quote escaped) when the param is present and not `all`.
5. **W_AUDIT_QUERY.json — global count:** add a `PG - Count Audit` node that executes `countQuery`; rewire `Parse → Count → Query → Format`; `PG - Query Audit` references the parse node for its data query and uses `alwaysOutputData` so a 0-row filtered page still responds; `B0 - Format Response` returns the real `total` from the count node.
6. **Verify:** both workflow Code nodes are syntactically valid JS; JSON valid; compose YAML valid.
