<objective>
Modify the Nginx gateway to generate a unique `$request_id` on every inbound request, include it
in the JSON access log under the field `request_id`, and propagate it to all upstream services
(n8n and Strapi) via the `X-Request-ID` HTTP header.

Purpose: Establish the correlation ID source. Every downstream service receives the same ID that
appears in the nginx access log, making end-to-end trace reconstruction possible by grepping
log files for the same ID value.

Output:
- `infra/gateway/nginx.conf` — updated log_format + proxy header in all proxy locations
- `infra/gateway/proxy_params` — X-Request-ID added to shared proxy params
</objective>

  <name>Task 1: Add request_id to nginx log format and update proxy_params</name>
  <files>infra/gateway/nginx.conf, infra/gateway/proxy_params</files>
  <action>
    Make two changes to nginx.conf and one change to proxy_params:

    CHANGE 1 — nginx.conf log_format:
    Replace the existing `log_format json_audit` block (lines 46-55) with an updated version
    that appends `"request_id":"$request_id"` as the last field before the closing brace.
    The new log_format must be:

    ```nginx
    log_format json_audit escape=json
      '{"time":"$time_iso8601",'
       '"addr":"$remote_addr",'
       '"proxy_ip":"$realip_remote_addr",'
       '"method":"$request_method",'
       '"uri":"$request_uri",'
       '"status":$status,'
       '"bytes":$body_bytes_sent,'
       '"ua":"$http_user_agent",'
       '"rt":$request_time,'
       '"request_id":"$request_id"}';
    ```

    Note: `$request_id` is a built-in nginx variable (nginx >= 1.11.0). No map block, no set
    directive, no additional module is required. nginx:1.27 supports it natively.

    CHANGE 2 — proxy_params: Add the following line after the last `proxy_set_header` line
    (after `proxy_set_header Connection "";`):

    ```nginx
    proxy_set_header X-Request-ID $request_id;
    ```

    This propagates the correlation ID to all proxy locations that use `include /etc/nginx/proxy_params`
    (the n8n routes: @whatsapp_get/post, @instagram_get/post, @messenger_get/post,
    /v1/customer/, /v1/internal/, /v1/admin/).

    CHANGE 3 — nginx.conf inline Strapi proxy locations:
    The three Strapi proxy locations (/v1/strapi/api/orders, ^~ /v1/strapi/, ^~ /v1/portal/)
    use inline proxy_set_header directives and do NOT include proxy_params. Add
    `proxy_set_header X-Request-ID $request_id;` to each of these three location blocks,
    immediately after the existing `proxy_set_header X-Forwarded-For` line in each block.

    For /v1/strapi/api/orders (around line 358):
    ```nginx
    proxy_set_header Host cms;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Request-ID $request_id;   # ADD THIS LINE
    proxy_read_timeout 15s;
    ```

    For ^~ /v1/strapi/ (around line 389):
    ```nginx
    proxy_set_header Host cms;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Request-ID $request_id;   # ADD THIS LINE
    proxy_read_timeout 30s;
    ```

    For ^~ /v1/portal/ (around line 423):
    ```nginx
    proxy_set_header Host cms;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Request-ID $request_id;   # ADD THIS LINE
    proxy_read_timeout 30s;
    ```

    Do NOT change any rate limiting, CORS headers, security headers, or any other part of the
    config. Only add the request_id log field and the X-Request-ID proxy header.
  </action>
