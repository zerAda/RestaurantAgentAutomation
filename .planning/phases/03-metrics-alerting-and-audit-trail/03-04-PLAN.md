<objective>
Add fire-and-forget audit write nodes to the three inbound adapter workflows (WhatsApp, Instagram,
Messenger) so every inbound execution is recorded in ops.workflow_audit.

Purpose: AUDIT-02 requires that W_IN_WHATSAPP, W_IN_INSTAGRAM, and W_IN_MESSENGER write audit
entries on execution start and completion. This plan patches the three JSON workflow files by
injecting two HTTP Request nodes into each — one at the start (after the fast ACK response),
one at the end of the success path.

Output:
- `workflows/W1_IN_WA.json` — patched with audit hooks
- `workflows/W2_IN_IG.json` — patched with audit hooks
- `workflows/W3_IN_MSG.json` — patched with audit hooks

Read the existing `workflows/W1_IN_WA.json`. Parse it as JSON. Add the following nodes and

**Nodes to add:**

**Node A — Code: Build audit-start payload** (insert AFTER "RESP - 200 ACK" node, on its output):
```json
{
  "id": "wa-audit-start-build",
  "name": "Audit - Build Start Payload",
  "type": "n8n-nodes-base.code",
  "typeVersion": 2,
  "position": [-1550, -100],
  "parameters": {
    "language": "javascript",
    "jsCode": "const ts = new Date().toISOString();\nreturn [{ json: {\n  _audit_payload: {\n    workflow_name: $workflow.name,\n    workflow_id: $workflow.id,\n    execution_id: $execution.id,\n    channel: 'whatsapp',\n    status: 'started',\n    started_at: ts,\n    correlation_id: $json._timing?.correlation_id || null,\n    tenant_id: $json.tenantId || null,\n    metadata_json: { msg_id: $json.metadata?.msgId || null }\n  },\n  ...$json\n}}];"
  }
}
```

**Node B — HTTP Request: POST to W_AUDIT_WRITE (fire-and-forget):**
```json
{
  "id": "wa-audit-start-write",
  "name": "Audit - Write Start (fire-forget)",
  "type": "n8n-nodes-base.httpRequest",
  "typeVersion": 4,
  "position": [-1350, -100],
  "parameters": {
    "method": "POST",
    "url": "http://n8n-main:5678/webhook/v1/internal/audit-write",
    "sendBody": true,
    "contentType": "raw",
    "rawContentType": "application/json",
    "body": "={{ JSON.stringify($json._audit_payload) }}",
    "options": {
      "timeout": 3000,
      "ignoreResponseCode": true
    },
    "continueOnFail": true
  }
}
```

**Node C — (at the END of the main success path) Code: Build audit-complete payload:**
Find the last meaningful node in the workflow's success path (the final Code or Set node before
the workflow ends). Add this AFTER it:
```json
{
  "id": "wa-audit-complete-build",
  "name": "Audit - Build Complete Payload",
  "type": "n8n-nodes-base.code",
  "typeVersion": 2,
  "position": [LAST_X + 250, LAST_Y],
  "parameters": {
    "language": "javascript",
    "jsCode": "const now = Date.now();\nconst startedAt = $json._timing?.inbound_received_at || new Date().toISOString();\nconst startMs = new Date(startedAt).getTime();\nconst durationMs = Math.round(now - startMs);\nreturn [{ json: {\n  _audit_payload: {\n    workflow_name: $workflow.name,\n    workflow_id: $workflow.id,\n    execution_id: $execution.id,\n    channel: 'whatsapp',\n    status: 'completed',\n    completed_at: new Date(now).toISOString(),\n    duration_ms: durationMs,\n    correlation_id: $json._timing?.correlation_id || null,\n    tenant_id: $json.tenantId || null\n  }\n}}];"
  }
}
```

**Node D — HTTP Request: POST audit-complete (fire-and-forget):**
Same structure as Node B but id=`wa-audit-complete-write`, name=`Audit - Write Complete (fire-forget)`.

**Connections to add:**
- `"RESP - 200 ACK"` main output -> `"Audit - Build Start Payload"` (add to connections object)
- `"Audit - Build Start Payload"` -> `"Audit - Write Start (fire-forget)"`
- Connect "Audit - Write Start" to the NEXT node that "RESP - 200 ACK" was previously connected to
  (so the main flow continues through the audit node, not around it). Actually: keep the existing
  connection from "RESP - 200 ACK" to its downstream node intact. The audit start chain is a
  PARALLEL branch from "RESP - 200 ACK" — n8n supports multiple output connections from one node.
  Add as an additional connection from "RESP - 200 ACK".
- `"Audit - Build Complete Payload"` -> `"Audit - Write Complete (fire-forget)"`
- Connect the last node in the success path -> `"Audit - Build Complete Payload"`

The key constraint: `continueOnFail: true` on both HTTP Request nodes ensures audit failures
do NOT stop the main workflow. This is non-negotiable for METR availability.

After patching, the JSON must remain valid. Verify with `JSON.parse()`.
