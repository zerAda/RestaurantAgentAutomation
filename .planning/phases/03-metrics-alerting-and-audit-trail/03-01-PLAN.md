<task type="auto">
  <name>Task 2: Nginx config — structured rate-limit hit logging</name>
  <files>infra/gateway/nginx.conf</files>
  <action>
Edit `infra/gateway/nginx.conf` to add two changes:

**Change 1:** Add a new `log_format` named `json_ratelimit` immediately after the existing
`json_audit` format block (around line 46-55). Insert:

```nginx
log_format json_ratelimit escape=json
  '{"time":"$time_iso8601",'
   '"level":"WARN",'
   '"event":"rate_limit_hit",'
   '"addr":"$remote_addr",'
   '"uri":"$request_uri",'
   '"method":"$request_method",'
   '"status":$status,'
   '"ua":"$http_user_agent"}';
```

Note: `$limit_req_zone` is NOT a built-in nginx variable — nginx does not expose which zone
triggered the limit in the access log. Zone name appears only in nginx stderr [warn] lines
(emitted by limit_req_log_level warn), not in the structured JSON format. Do NOT include
`$limit_req_zone` in the log_format as it will always expand to empty string.

**Change 2:** Inside the `server { }` block, after the existing `access_log` line
(`access_log /var/log/nginx/access.json json_audit;`), add:

```nginx
  # Rate-limit hit log: captures all 429 responses with IP and URI (METR-03)
  # Writes to stderr so these lines appear in `docker logs gateway`
  # limit_req_log_level warn emits a nginx [warn] line for every delayed/rejected request
  # Format: [warn] ... limiting requests, excess: X.XXX by zone "meta_inbound", client: IP, ...
  # Operators: docker logs current-gateway-1 2>&1 | grep "limiting requests"
  limit_req_log_level warn;
```

This sets nginx to emit `[warn]` level log lines (visible in stderr / `docker logs gateway`)
for every request rejected by a `limit_req` zone. The log line format nginx uses is:
`[warn] ... limiting requests, excess: X.XXX by zone "meta_inbound", client: IP, ...`
This is sufficient for METR-03: operators run `docker logs gateway 2>&1 | grep "limiting requests"`
to see throttled IPs with zone, IP, and URI.

The `access_log` line already logs all 429s (including rate-limited ones) to
`/var/log/nginx/access.json` via `json_audit` format. No additional file needed since nginx
containers use stdout/stderr logging (the json-file Docker logging driver captures both).

Do NOT change the `log_format json_audit` or `access_log` directives — they must remain intact.
Do NOT add a second `access_log` directive pointing to a separate file (tmpfs-mounted container
does not have a persistent log directory outside /var/log/nginx which is in-container memory only).
