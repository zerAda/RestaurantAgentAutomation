<objective>
Build the entitlement audit + cache-invalidation hook (AUD-01 + AUD-02): a PURE, Strapi-free helper
`audit-hook.ts` (testable without booting Strapi) and two thin `lifecycles.ts` adapters on
`tenant-entitlement` and `product-module`. On every entitlement change the hook writes an
`entitlement_audit_log` row (who/what/when/old→new) via raw Knex AND issues an exact-key Redis `DEL` of
`ralphe:entitlement:{tenant_id}:{module_key}` so a revoked/expired entitlement cannot survive in cache.

Purpose: This is the core of Phase 19. The placement + cache-key + uuid decisions are settled by 19-01
(ADR 0003 + the migration), and the validation harness is built by 19-03 (the node-test + CI gate that
this plan's helper must satisfy). This plan factors the logic into a pure helper (the testability
keystone) and wires it through the Strapi-5 lifecycle event shape — capturing the old value in the
`before*` hooks (Strapi 5 `after*` carry none) and the actor via `strapi.requestContext`.

Output: 1 new pure helper + 2 new `lifecycles.ts` (one created on each content type, neither exists yet).
All files are DISJOINT from 19-01 (the ADR + migration) and 19-03 (CI fixtures/assertions/yml + node-test
+ harness), so this runs as an independent executor pass. It is Wave 2 because its node-test consumes the
19-03 harness + fixtures and its helper is the seam the 19-03 test drives.

🔴 VPS DEFERRED: rebuilding the CMS so these `lifecycles.ts` + `audit-hook.ts` take effect, and confirming
the prod Redis the `DEL` targets is the SAME Redis the Phase-20 guard reads, are deferred to a
prod-connected session.
</objective>
