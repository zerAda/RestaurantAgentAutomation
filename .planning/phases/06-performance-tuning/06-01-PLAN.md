  <action>
Create `admin-dashboard/scripts/` directory (mkdir -p) and create `check-bundle-size.cjs`.

This is a Node.js CommonJS script (`.cjs` so it runs with `node` regardless of package.json
type:module). It does:

1. Reads all `.js` files in `admin-dashboard/dist/assets/` using `fs.readdirSync` + `fs.statSync`.
2. Sums their byte sizes to get `totalBytes`.
3. Converts to KB: `totalKB = totalBytes / 1024`.
4. Prints each JS file and its size in KB.
5. Prints `TOTAL_JS_KB: {number}`.
6. Counts JS chunk files: `chunkCount = jsFiles.length`.
7. Identifies the entry bundle: the file matching `index-*.js` or the smallest named chunk.
8. Checks PERF-08 acceptance criteria (both must pass):
   - `chunkCount >= 5` — confirms code splitting is structurally active (lazy() produces one chunk per route)
   - `entryKB <= 30` — confirms the entry bundle (index-*.js) is 30KB or less
9. Prints `CHUNKS: {chunkCount}` and `ENTRY_KB: {entryKB}`.
10. If both conditions are met: prints `PERF-08: PASS — code splitting active ({chunkCount} chunks, entry {entryKB}KB)` and exits 0.
11. If either condition fails: prints `PERF-08: FAIL — {reason}` and exits 1.

NOTE: The monolithic baseline no longer exists in git. The PERF-08 requirement has been updated
to use this structural proxy: 5+ chunks confirms lazy() is working, entry ≤30KB confirms the
initial download is significantly reduced vs a monolithic build. This is per REQUIREMENTS.md
as of 2026-03-28.

If env var `BUNDLE_BASELINE_KB` is set, also compare: `reduction = (baseline - totalKB) / baseline * 100`
and print `REDUCTION: {reduction}% vs baseline`. This is informational; does not override the
structural check.
