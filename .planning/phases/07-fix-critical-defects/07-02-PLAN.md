**W_AUDIT_QUERY.json change (B0-Format-Response node jsCode):**

Locate the node with `"id": "audit-query-format"` (name: "B0 - Format Response"). Replace ONLY the `jsCode` string in that node's parameters.

Current jsCode:
```javascript
var items = $input.all().map(function(i) { return i.json; });
return [{ json: { rows: items } }];
```

New jsCode:
```javascript
var cfg = $('B0 - Parse Params').first().json;
var items = $input.all().map(function(i) { return i.json; });
return [{ json: { data: items, total: items.length, page: cfg.page, limit: cfg.pageSize } }];
```

This makes the response match the `AuditResponse` TypeScript interface: `{ data: AuditRecord[], total: number, page: number, limit: number }`.

Known limitation: `total` reflects only the count of items in the current page, not the overall count across all pages. The countQuery exists in B0-Parse-Params but is never executed by a second PG node. This is acceptable as a first fix — record as tech debt for a future phase.

CRITICAL constraints for W_AUDIT_QUERY.json:
- The jsCode must be a valid JSON string with \n for newlines and \" for quotes
- Preserve ALL other nodes (audit-query-webhook, audit-query-parse, audit-query-pg, audit-query-respond) unchanged
- Preserve ALL connections unchanged
- Preserve the CREDENTIAL_ID_PLACEHOLDER in audit-query-pg — credential wiring is a VPS activation step
- Write the entire file using the Write tool to avoid JSON escaping issues
